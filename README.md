# Codex FDE 키트 · edohynix-kit

업무 요구를 데이터·규칙·기능·검증으로 연결하는 프로젝트용 스킬과 실행 도구입니다. 현재 프로젝트의 지침·권한·실행 제한을 우선하며, 필요한 단계의 스킬만 읽습니다.

## 1. 가져오기와 설치

### Codex에 한 번에 요청하기

> https://github.com/im2do/edohynix-kit.git 을 clone하고, 키트 README 절차대로 현재 과제 폴더에 하네스 전체를 설치·적용·검증해줘. 기존 과제 지침과 파일은 보존해줘.

이미 clone했다면 **“edohynix-kit의 README 절차대로 하네스 전체를 설치·적용·검증해줘”**라고 요청합니다. `git clone`은 다운로드만 수행합니다. **README대로 설치하라는 요청은 아래 준비부터 적용·검증까지를 포함하며, 스킬 복사만 하고 끝내지 않습니다.**

### 설치를 수행하는 Codex의 절차

1. **작업 위치와 지침 확인:** 현재 과제 README·AGENTS.md 등 적용 지침과 허용된 실행 방식을 먼저 확인합니다. 이 키트는 기존 지침을 대체하지 않습니다. 설치 대상은 실제 과제 폴더이며, 키트 원본 폴더나 홈 폴더가 아닙니다. 대상이 불명확하면 확인합니다.
2. **가져오기:** 아래 저장소를 `tools/edohynix-kit`에 clone합니다. 이미 있다면 출처와 현재 파일을 확인해 재사용하며 삭제·덮어쓰기·강제 갱신하지 않습니다. 다른 경로에 clone했다면 명령의 키트 경로를 실제 경로로 바꿉니다.
3. **전체 설치:** `scripts/bootstrap_codex.py`를 읽고 아래 명령으로 미리보기부터 실행합니다. 별도 프로필 지정이 없으면 `app`을 사용합니다. 계획에 충돌이 없고 현재 권한·지침에 부합하면 `--apply`까지 이어서 실행합니다. 이는 스킬과 참고자료, 실행 도구, 운영 지침, 상태 파일을 함께 설치합니다.
4. **기존 설치 보호:** 충돌이나 설치 실패가 있으면 같은 명령을 반복하지 않습니다. 기존 파일과 설치 계획을 읽기 전용으로 대조해 이미 설치된 구성·누락·차이를 보고합니다. 기존 진행 기록은 초기화하지 않고, 변경이 필요한 충돌은 먼저 알립니다. `sudo`, 권한 우회, 전역 설정 변경은 하지 않습니다.
5. **운영 지침 적용:** 설치된 `FDE_HARNESS.json`을 읽고 `guide`, `package`, `progress`, `state`가 가리키는 실제 파일과 안내를 확인합니다. 기존 AGENTS.md 때문에 `FDE_INSTRUCTIONS.md`가 만들어졌다면 그 파일도 직접 읽습니다. 기존 과제 지침과 충돌하는 내용은 적용하지 않습니다. `fde-route`, `fde-track`의 SKILL.md와 관련 기록 형식을 읽고 이후 작업에 적용합니다. 나머지 스킬·참고자료는 해당 작업에 필요할 때 읽습니다.
6. **검증:** 아래 확인 목록을 점검하고 짧게 결과를 보고합니다. 설치 요청만으로 과제 구현이나 브라우저 자동 조작을 시작하지 않습니다. 설치 후 별도의 적용 요청을 기다릴 필요는 없지만, 구현은 사용자의 다음 작업 지시에 따릅니다.

설치·적용 확인 목록:

- `FDE_HARNESS.json`의 프로필·스킬 목록·지정 경로가 실제 설치 파일과 일치하는지 확인합니다. `app`은 스킬 11개이며 `.agents/skills/`의 각 SKILL.md와 해당 참고자료까지 원본과 대조합니다.
- `fde-harness/`의 스크립트·가이드와 지정된 운영 지침, `FDE_PROGRESS.json`, `FDE_WORKSTATE.md`가 존재하고 JSON을 읽을 수 있는지 확인합니다. 기존 기록이 있으면 유지합니다.
- 아래 상태 조회를 실행하고 PDF 엔진은 `python3 fde-harness/scripts/pdf_read.py --doctor`로 확인합니다. 누락된 의존성은 보고하며 추가 설치는 현재 권한과 사용자 지시를 따릅니다. 엔진 발견만으로 실제 PDF 추출이 검증됐다고 보고하지 않습니다.
- 스킬 목록을 확인할 수 있으면 등록 여부까지 확인합니다. 확인할 수 없다면 **파일 배치 확인 / 현재 세션 인식 미확인**으로 구분합니다. 필요하면 해당 SKILL.md를 직접 읽어 적용하고, 세션을 임의로 종료하거나 재시작하지 않습니다.
- 결과는 **설치 위치 / 설치된 구성 / 실제 읽고 적용한 지침·스킬 / 누락·미검증 / 필요한 다음 행동**으로 짧게 보고합니다. 이후 변경 작업에서는 완료·미완료·미검증·확인 필요를 기록과 함께 갱신합니다.

### 실행 명령

Python 3.10 이상과 Git이 필요합니다. PDF 추출 엔진 외에는 기본 스크립트에 별도 Python 패키지가 필요하지 않습니다. 아래 명령은 실제 환경에서 허용된 실행 방식으로 사용합니다.

**프로젝트 작업 폴더에서** 실행합니다. 키트 원본 폴더 안에 설치하지 않습니다.

```bash
git clone --depth 1 https://github.com/im2do/edohynix-kit.git tools/edohynix-kit
# 파일을 쓰지 않고 설치 경로·충돌을 확인
python3 tools/edohynix-kit/scripts/bootstrap_codex.py --workspace . --profile app
# 확인한 구성 적용
python3 tools/edohynix-kit/scripts/bootstrap_codex.py --workspace . --profile app --apply
```

| 작업 | 프로필 | 스킬 |
|---|---|---|
| 웹앱·업무 화면 | `app` | 공통 10개 + UI 1개 |
| 데이터 분석 | `data` | 공통 10개 |
| 문서·보고서 | `document` | 공통 10개 |

기존 `README.md`는 수정하지 않습니다. `AGENTS.md`가 있으면 보존하고 `FDE_INSTRUCTIONS.md`를 별도로 만듭니다. 기존 파일 충돌이나 작업 폴더 밖 심볼릭 링크는 거부합니다. 설치 중 OS 쓰기 오류가 나면 일부 새 파일이 남을 수 있으므로 생성 목록을 확인하고 재설치를 반복하지 않습니다.

설치 후에는 위 절차의 운영 지침 적용과 검증까지 이어서 수행합니다. 새 대화에서 재개할 때만 다음과 같이 요청할 수 있습니다.

> FDE_HARNESS.json의 운영 지침과 현재 진행 기록을 읽고 이어가줘. 기존 요구를 유지하며 필요한 스킬을 적용하고, 완료·미완료·미검증·확인 필요를 보여줘.

### 설치 없이 사용

> tools/edohynix-kit/skills/fde-route/SKILL.md와 tools/edohynix-kit/skills/fde-track/SKILL.md를 읽고 필요한 스킬만 적용해줘. 스크립트는 tools/edohynix-kit/scripts에서 실행해. 기존 작업 기록은 초기화하지 말고 읽어서 이어가줘.

상태 기록이 **없고 쓰기가 허용될 때만** 프로젝트 폴더에서 초기 생성합니다.

```bash
python3 tools/edohynix-kit/scripts/fde_state.py init --workspace .
```

이 명령은 `FDE_PROGRESS.json`만 만듭니다. 스킬 설치나 전체 대화 백업은 하지 않습니다. 파일 쓰기·실행이 불가능하면 미저장·미실행 범위와 이어갈 메모를 남깁니다.

## 2. 필요한 스킬 선택

| 상황 | 스킬 | 확인할 출력 |
|---|---|---|
| 시작·재개·방향 변경 | `fde-route` | 지금 필요한 단계 |
| 목표·권한·예외 미정 | `fde-define` | 담당자에게 확인할 쟁점 |
| PDF 읽기 | `fde-pdf-read` | 쪽수·추출 실패·시각 확인 범위 |
| 표·결합·변환·매핑 | `fde-data` | 행·ID·단위·중복·원문 위치 |
| 규정·담당자 답 적용 | `fde-rules` | 조건·경계·예외·출처 |
| 확정된 기능 구현 | `fde-build` | 작은 기능 하나와 변경 근거 |
| 업무 화면 구성 | `fde-ui` (`app`) | 판단·다음 행동·오류가 보이는 화면 |
| 누적 요구 추적 | `fde-track` | 완료·미완료·미검증·확인 필요 |
| 결과 검증·오류 추적 | `fde-verify` | 독립 기대값·실제값·첫 불일치 |
| 기능별 전체 점검 | `fde-project-review` | 입력·예외·검증·출력·남은 확인 |
| 결과 전달 | `fde-deliver` | 산출물·실행 방법·검증·한계 |

스킬 이름으로 요청하거나 `skills/<이름>/SKILL.md`를 직접 읽게 합니다. 실제 작업 순서와 담당자 답변 전달 방법은 [작업 흐름](guides/WORKFLOW.md)에 있습니다.

## 3. 상태 기록과 재개

- `FDE_HARNESS.json`: 설치 경로, 운영 지침, 사용 스킬.
- `FDE_PROGRESS.json`: 목표·요구·검사·변경 이력의 기준 기록.
- `FDE_WORKSTATE.md`: 짧은 요약과 원문 위치 안내.
- `.agents/skills/`: 프로젝트에 복사된 스킬.
- `fde-harness/`: 스크립트·스킬·사용 안내.

설치 후 상태 조회:

```bash
python3 fde-harness/scripts/fde_state.py status --workspace . --format footer
```

새 대화에서는 현재 지침, 실제 상태 파일, 변경된 코드와 검증 기록을 먼저 읽습니다. 이전 요구를 지우거나 기록을 초기화하지 않습니다. 담당자 답변 원문·전체 대화·실행 로그는 별도로 저장해야 합니다.

Git 저장소를 갱신해도 이미 프로젝트에 복사된 스킬은 자동 갱신되지 않습니다. 기존 설치본을 덮어쓰지 말고 최신 키트의 필요한 `SKILL.md`를 직접 읽게 할 수 있습니다.

## 4. 기능별 프로젝트 리뷰

> $fde-project-review로 현재 솔루션을 읽기 전용으로 점검해줘. 실제 기능, 읽는 데이터, 중복·예외 처리, 구현 이유의 근거, 실제 검증, 출력과 영향, 미검증 사항을 한눈에 정리해줘.

출력은 **전체 흐름 → 기능별 점검표 → 결과에 영향을 주는 미확인 사항**입니다. 코드 확인·테스트 존재·실행 기록·화면 확인을 구분하고 미완료 기능도 남깁니다. 리뷰 요청만으로 코드·진행 기록을 바꾸거나 테스트·브라우저 자동 조작을 시작하지 않습니다.

[리뷰 스킬](skills/fde-project-review/SKILL.md) · [점검표 작성 기준](skills/fde-project-review/references/review-format.md)

## 5. 실행 도구

[도구별 명령·입력 형식·결과 해석](guides/TOOLS.md)에서 PDF 추출, CSV·JSON 점검, 매핑, 상태 추적, 근거 대조를 확인합니다. 스크립트는 구조·기록을 검사하며 업무 규칙 자체를 대신 결정하지 않습니다. 필요한 규칙은 확인된 원문으로 구현합니다.

특정 모델·외부 API 키·MCP 서버·자동 훅·전역 설정을 요구하지 않습니다. 플러그인 메타데이터는 지원 클라이언트에서만 사용하며 프로젝트 스킬 설치와 중복 등록하지 않습니다. 외부 라이브러리 설치와 자료 전송은 현재 환경의 권한을 따릅니다.
